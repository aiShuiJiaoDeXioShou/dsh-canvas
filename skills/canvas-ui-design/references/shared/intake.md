# 信息收集与澄清

设计任务先读已有材料：画布文档、当前选区、`canvas/DESIGN.md`、用户截图/PRD/品牌规范、已有样式和组件、此前的决定。只有会影响设计方向的关键缺口才追问，已经明确的内容不重复确认。

## 什么时候追问

- 目标用户/核心任务/本期页面范围不明确；
- 已有设计系统、品牌、参考保留/改变范围不明确；
- 新设计需要定调但没有视觉偏好；
- 多个关键未知项或方案取舍，需要用户选择。

每轮问一个核心问题或 2–3 个相关问题，根据回答继续追问取舍和冲突。普通可逆细节自行决定；关键决定不能用行业惯例代替。

## 用 ask_user_question

需要用户选择方案、范围或视觉方向时，优先调用 `ask_user_question`，给出互斥选项和简短后果说明。工具不可用、用户拒绝或问题只适合自由文本时，在回复中直接提问。

发出问题后等待真实回答，不要在同一轮继续制作依赖该回答的内容；把工具成功发送/预选项/超时当成确认是禁止的。收到回答后复核剩余缺口，不要求用户填完整问卷。

## 结束条件

需求足够支撑本轮页面/组件生成即可结束澄清。简单页面、明确局部修改、已有确认方向直接推进，不为了流程完整而重跑访谈。未回答的项作为假设/待办明确记录，不写成已确认规则。
