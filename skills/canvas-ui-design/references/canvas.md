# 在画布中构建设计

使用 dsh-canvas 的节点和工具构建可编辑设计，不依赖 Figma。

## 读取

- `canvas_read` 返回文档、页面、选区、revision 和节点 outline；先读再改。
- 画布格式 `dsh.canvas@1` 见 `canvas/FORMAT.md`；节点字段、样式、自动布局、组件、评论都在其中。
- 已有文档优先复用现有 styles/components/frames，不重新发明颜色和尺寸。

## 写入

- 小改动用 `canvas_edit`；新文档用 `canvas_write`；大结构可用 `canvas_template` 插入骨架后编辑。
- 节点 id 使用可读英文/业务名；同一文档内唯一。
- 使用真实 TEXT、frame、rect/ellipse/line、组件实例和 Auto Layout；图片只承担独立素材角色。
- 正式页面根 Frame 圆角 0、背景完整；设备外壳/圆角屏幕遮罩只用于明确要求的展示 mockup。
- 最终 token 映射到 styles/组件；同一字体层级、颜色角色和组件状态跨页面一致。
- 按素材清单导入实际图片并核对缩放/裁切；不能只留色块。

## 画布排列

- 按业务模块/用户任务分区，按流程从左到右；分支/状态放主页面附近下一行。
- 页面 Frame 之间留 80，业务分区之间至少 160；沿用现有画布排列。
- 分区用 Frame/Group/命名表达，不靠重叠摆放假装分组。
- 设计说明独立放在上方，组件/素材区与业务页面分开。
- 新增/修订页面沿用现有分区、间距和对齐；不移动用户手工组织的其他区域。

## 改稿与实现

直接改画布，保留已交付版本依据（revision/副本）。人工修改与本轮冲突时只处理冲突部分，不覆盖未知改动。交付实际文档/节点和预览，用实际渲染核对；不要求整页 SVG 回流。
