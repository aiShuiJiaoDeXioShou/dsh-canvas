# 设计审查

设计审查默认只读；除非用户同时要求修复。

## 证据来源

| 证据 | 能支持的结论 |
| --- | --- |
| `canvas_audit` 结果 | Frame 边界、可计算对比度、触控尺寸、裁切、引用问题 |
| 实际画布/导出渲染 | 文本截断、遮挡、留白、层级、风格与内容合理性 |
| 文档结构/组件实例 | 组件/样式使用、状态是否存在、实际宽高与布局 |
| 用户提供的原型/运行结果 | 已实际操作的跳转和反馈；画布静态稿不冒充运行验收 |

## 执行

1. 读取页面清单、`canvas/DESIGN.md`、Foundation/目标参考和 `canvas_read` 选区。
2. 运行 `canvas_audit`（page 或 node scope），记录 findings 与 skipped。
3. 查看实际画布或导出预览；对照参考同尺寸核对关键区块、文字、颜色、密度、素材和状态。
4. 需要查看具体节点时用 `canvas_read`/画布 UI；截图和实际渲染优先于节点数量。

## 重点

- 参考还原：逐页检查区块完整性、位置/尺寸、文字换行、颜色、密度、素材和状态；不能只判“风格相近”。
- 截图边界：根 Frame 圆角 0、完整不透明背景；设备 mockup 另标。
- 组件与图标：母版/实例宽高、padding、长标签、图标引用和缩放；触控容器至少 44×44。
- 内容与数据：滚动视口、自然内容、最后一项、图表文字/比例一致；选择控件有可辨识选项。
- 可读性：关键正文/辅助文字/动作标签的实际对比度；不能因 token 校验通过就推断达标。
- 画布组织：Frame 命名、分区、间距、无重叠和孤立容器。

## 输出

直接说明结论、主要问题、影响和证据；需要留存时在 `canvas/design/report.md` 记录严重程度、页面/节点、建议和复验结果。只报告真实发现与未检查项；不要用单个“通过”概括结构、视觉和交互三个不同结果。

- 有 `high` finding：仍需修订；
- 只有 skipped/无法检查项：明确列出，不能写“视觉审查通过”；
- 修复后只复验受影响部分。

## 完成

审查完成即结束；用户要求修复时再进入 [修改与回归](design-refactor.md)。
