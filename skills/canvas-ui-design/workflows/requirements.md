# 需求与页面场景

先复用用户已经给出的需求、截图、已有画布、PRD、参考图和工程规范。只有目标用户、核心任务、页面范围、已有设计方向或交付终点不明确时才追问；每轮问一个核心问题或 2–3 个相关问题，关键决定不要用行业惯例代替。用户已明确的部分直接使用，不重复访谈。

需要用户选择方案或范围时，优先调用 `ask_user_question`；工具不可用时在回复中直接提问，并停止本轮制作。相关方法与退出条件见 [信息收集](../references/shared/intake.md)。

## 输出到画布 brief

新设计或较大改版在 `canvas/design/brief.md` 记录（简单修改可合并到回复）：

- 产品目标、目标用户、核心任务；
- 本轮页面范围、不做的范围；
- 页面/状态清单：正常、空、加载、错误、权限、离线的适用项；
- 已有设计系统、参考图和用户偏好；默认是否为 iPhone 16 + Neutral；
- 待解决问题和已知假设。

需求是设计生成依据，不要为了 brief 停掉实际页面制作；简单页面可以边做边补。完整产品规则需要 PRD 时，把要求写进 brief，不伪造外部 PRD。

## 与参考的关系

用户只提供 App 链接或描述、缺少真实运行材料时，说明证据缺口，可用公开资料和用户录屏补充；不要声称已经还原未观察到的交互。已有设计足够时直接进入页面制作和参考落实。

## 完成

需求足够支撑本轮页面/组件生成即可结束澄清，不要为可逆细节反复询问。进入 [信息架构](information-architecture.md) 或直接开始页面。
