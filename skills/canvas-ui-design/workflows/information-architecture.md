# 信息架构与页面状态

从核心用户任务整理页面层级、入口、返回路径和关键操作；把业务行为与视觉偏好分开。

## 页面清单

多页任务在 `canvas/design/manifest.json` 记录：

```json
{
  "pages": [
    { "id": "home", "purpose": "查看今日心情", "entry": "tab", "states": ["normal", "empty", "loading", "error"], "nodeId": null }
  ]
}
```

只保留对本任务适用的状态。保存、取消、失败恢复和返回路径写在对应页面旁，不另造一套重复清单。

## 画布组织

- 按业务模块/用户任务分区，按流程从左到右；分支和同页状态放在主页面附近下一行。
- 页面 Frame 之间留净距 80；业务分区之间至少 160。沿用已有画布的排列和标签风格。
- 页面名称表达业务，不用“Frame 1/最终版”这类临时命名。
- 先确定页面清单与顺序，再批量生成；局部修改不重建整个 IA。

## 交互

交互复杂时先用线框/流程说明关键路径，但线框不替代复杂页面的视觉设计。静态画布无法验证真实交互时，明确标注未验证，不虚构。

## 完成

页面/状态、入口、返回和适用异常状态明确后，进入 [页面设计](screen-designer.md)。
